================================================================
SINGLE PURPOSE
================================================================

Alcove replaces Chrome's new tab page with a customisable start
page: a wallpaper, a clock, a search box, shortcut tiles, widgets,
and a set of small utilities the user opens from a dock or a grid.


================================================================
PERMISSION JUSTIFICATIONS  (one field each)
================================================================

storage
Stores the user's own settings - layout, theme, wallpaper choice,
quick links, widget placement, and which tools are enabled - so their
new tab looks the same each time it opens.

unlimitedStorage
Wallpapers are images the user uploads, kept in IndexedDB on their
device. A small library of photos exceeds the default storage quota,
and exceeding it would silently fail to save the user's own image.

alarms
Schedules the reminders and countdown timers the user creates. An
alarm is the only timer that survives the service worker being
suspended; a setTimeout would be discarded and the reminder would
never fire.

notifications
Displays the reminder or timer message at the moment it fires. Used
only for reminders and timers the user set themselves.

search
Runs the query the user types in the new tab's search box through
their own default search engine, instead of navigating to a
hard-coded engine URL.

favicon
Reads Chrome's local favicon cache to draw icons for the user's saved
quick links, so their list of links never has to be sent to a
third-party icon service.

history
Optional and off by default. When the user switches on the shortcut
tile row, this reads their recently visited pages to draw those
tiles. The titles and addresses are displayed on the user's own new
tab and are never transmitted anywhere.

topSites
Optional and off by default. An alternative source for the same
shortcut tile row, selected by the user in settings, showing their
most visited sites instead of the most recent.

host permissions  (one combined field)
Alcove contacts only the services required by features the user has
chosen, directly from the extension's own page. There is no server
belonging to the developer, so nothing is proxied or collected.
- api.open-meteo.com, geocoding-api.open-meteo.com: forecast and city
  lookup for the weather widget. No account or API key is involved.
- open.er-api.com: current exchange rates for the currency converter
  tool, cached for a day.
- www.google.com/s2/favicons, icons.duckduckgo.com: fetches an icon
  for a site the user saved as a quick link, once per hostname and
  then cached locally. Only the site's origin is ever sent, never a
  path or query, and this can be switched off in settings.
- www.youtube.com: reads public oEmbed data to show track titles for
  a playlist the user added.
One origin is optional and requested in context: news.google.com,
asked for when the user picks their first news topic and handed back
when they remove their last one.

Two further hosts are contacted by the My IP tool and are
deliberately NOT in the manifest, because both answer with
Access-Control-Allow-Origin: * and need no host permission:
- ipwho.is: reports back the public IP address the connection came
  from, with the city and network operator it maps to.
- api.ipify.org: reports the IPv4 address, and is asked only when the
  connection reached the first service over IPv6.
Both are contacted only while that tool is open, carry no account or
key, and send nothing about the user beyond the request itself.


================================================================
REMOTE CODE  -  answer: No
================================================================

Select "No, I am not using remote code".

Why that is the correct answer: the extension's CSP is
script-src 'self'. No JavaScript, WebAssembly or CSS is loaded from
outside the package into any extension page, and nothing is eval'd.
Every script that runs in an extension context ships in the zip.

The one thing worth understanding before you click it: the music
feature frames one third-party page in an iframe
(player-html-ashy.vercel.app, allowed via frame-src). That page runs
its own code in its own origin - exactly like an embedded YouTube or
Maps player - and cannot execute anything in the extension's
context. Framing remote content is not the same as including remote
code, which is why "No" is accurate.

If the form gives you a free-text box alongside the answer, say so
plainly rather than leaving it blank:

  Alcove executes no remote code; its CSP is script-src 'self' and
  all scripts ship in the package. It does embed one third-party
  page in an iframe for YouTube playback, which runs in its own
  origin and cannot execute code in the extension.


================================================================
DATA USAGE DISCLOSURES
================================================================

Tick:

  Web history
    Only if you keep the shortcut tile row. Read on the device to
    draw the tiles; never transmitted.

  Location
    Two features, both user-initiated. The weather widget sends the
    coordinates of a city the user picked to Open-Meteo. The My IP
    tool receives back the city and network its lookup service reads
    from the connection. Neither uses the device's location API, but
    both are location data crossing the wire, so tick it.

Do NOT tick Authentication information or Personal communications.
Both applied to the AI chat removed before 1.0.0: there is no API key to
store and no message sent to any model provider. Leaving them ticked
would declare collection this package does not perform.

Then tick all three certifications - all three are true of this
extension:
  - I do not sell or transfer user data to third parties, outside of
    the approved use cases
  - I do not use or transfer user data for purposes unrelated to my
    item's single purpose
  - I do not use or transfer user data to determine creditworthiness
    or for lending purposes
